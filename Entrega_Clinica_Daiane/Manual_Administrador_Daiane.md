Configuração de Permissões\n\n#### 2.1 Permissões por Módulo\n\n| Módulo | Permissões Visíveis | Permissões de Ação |\n|--------|---------------------|--------------------|\n| **Turmas** | `turmas.view`, `turmas.presenca` | `turmas.create`, `turmas.update`, `turmas.delete` |\n| **Atendimentos** | `atendimentos.view`, `agenda.presenca`, `consumir.sessao` | `atendimentos.create`, `atendimentos.update` |\n| **Tratamentos** | `tratamentos.view` | `tratamentos.create`, `tratamentos.update`, `tratamentos.status` |\n| **Financeiro** | `financeiro.view`, `financeiro.receive` | `financeiro.create`, `financeiro.update` |\n| **Pacientes** | `pacientes.view`, `pacientes.create`, `pacientes.update`, `pacientes.delete` | Completo |\n\n#### 2.2 Adicionar Nova Permissão\n\n1. Acessar `Painel > Configurações > Permissões`\n2. Clicar em `Nova Permissão`\n3. Preencher:\n   - Nome da permissão (ex: `turmas.create`)\n   - Módulo pai\n   - Nível de acesso (View, Create, Update, Delete)\n   - Perfis que terão acesso\n4. Salvar e testar\n\n#### 2.2 Remover Permissão\n\n1. Acessar `Painel > Configurações > Permissões`\n2. Localizar a permissão a remover\n3. Clicar em `Remover`\n4. Confirmar remoção\n5. Verificar se algum usuário foi afetado\n\n---\n\n### 3. Manutenção de Banco de Dados\n\n#### 3.1 Backup de Rotina\n\n##### 3.1.1 Frequência\n\n- Diária: Após horário de pico (18:00)\n- Semanal: Todo domingo, 02:00\n- Mensal: Último domingo do mês, 02:00\n\n##### 3.1.2 Procedimento\n\n1. Acessar o servidor MySQL\n2. Executar comando:\n\n```bash\nmysqldump -u saas clinic_000001 > backup_000001_$(date +%Y%m%d).sql\nmysqldump -u saas clinic_000005 > backup_000005_$(date +%Y%m%d).sql\nmysqldump -u saas saas_central > backup_central_$(date +%Y%m%d).sql\n```\n\n2. Copiar arquivos para diretório de backup:\n   `/var/backups/ljsmartclinic/`\n\n3. Verificar integridade:\n```bash\ngzip -t /var/backups/ljsmartclinic/backup_*.sql.gz\n```\n\n##### 3.1.3 Retenção\n\n- Manter backups dos últimos 14 dias\n- Manter backups mensais por 12 meses\n- Testar restauração a cada 30 dias\n\n#### 3.2 Atualização de Permissões\n\n##### 3.2.1 Quando Conceder Novas Permissões\n\n- Quando novo módulo for adicionado\n- Quando função do usuário mudar\n- Quando solicitação for formal por escrito\n- Após aprovação do gestor\n\n##### 3.2.2 Procedimento\n\n1. Identificar a permissão necessária\n2. Verificar se já existe no sistema\n3. Se não existir, criar nova entrada em `role_permission`\n4. Conceder ao perfil de usuário adequado\n5. Testar acesso do usuário\n5. Documentar na mudança de serviço\n\n##### 3.2.3 Exemplo: Conceder `turmas.create` ao perfil Fisioterapia\n\n```sql\nINSERT IGNORE INTO clinic_000005.role_permission (role_id, permission_id)\nVALUES (6, [id_do_pacotes_create]);\n```\n\nOnde `role_id = 6` é o perfil Auxiliar/Fisioterapia.\n\n---\n\n### 4. Solução de Problemas Comuns\n\n#### 4.1 Acesso Negado a Módulo\n\n**Sintomas:** Usuário tenta acessar módulo e recebe erro 403 ou mensagem de permissão negada.\n\n**Causas Possíveis:**\n\n1. Usuário não tem permissão atribuída\n2. Permissão expirada ou revogada\n3. Perfil de usuário incorreto\n4. Cache do sistema desatualizado\n\n**Soluções:**\n\n1. Verificar permissões do usuário em `Painel > Usuários > [nome] > Permissões`\n2. Conceder permissão necessária\n3. Limpar cache do sistema: `php artisan cache:clear`\n4. Verificar perfil do usuário está correto\n\n#### 4.2 Sistema Lento\n\n**Sintomas:** Páginas carregam devagar, tempos de resposta altos.\n\n**Causas Possíveis:**\n\n1. Cache desatualizado\n2. Consultas bancárias não otimizadas\n3. Muitos logs acumulados\n4. Recursos do servidor insuficientes\n\n**Soluções:**\n\n1. Limpar todos os caches: `php artisan cache:clear && php artisan route:clear && php artisan view:clear`\n2. Verificar lentidão de queries no MySQL\n3. Verificar logs do sistema: `tail -f storage/logs/laravel.log`\n4. Verificar recursos do servidor (CPU, Memória)\n5. Verificar se há processos rodando desnecessários\n\n#### 4.3 Tela Branca ou Erro 500\n\n**Sintomas:** Página branca ou mensagem \"500 Internal Server Error\".\n\n**Causas Possíveis:**\n\n1. Erro fatal em PHP\n2. Arquivo .htaccess corrompido\n3. Permissões de arquivo incorretas\n4. Memória insuficiente\n\n**Soluções:**\n\n1. Verificar logs do erro: `tail -n 50 storage/logs/laravel.log`\n2. Verificar permissões dos arquivos: `chmod -R 755 pasta/sistema`\n3. Verificar memória PHP: `php -i | memory_limit`\n4. Restart do PHP-FPM: `service php8.3-fpm restart`\n5. Reverter mudanças recentes se aplicável\n\n#### 4.4 Perfil de Usuário Incorreto\n\n**Sintomas:** Usuário tem acesso a módulos que não deveria ou falta acesso a módulos que deveria ter.\n\n**Soluções:**\n\n1. Verificar perfil do usuário em `Painel > Usuários`\n2. Confirmar `clinic_id` correto\n3. Verificar permissões atribuídas\n4. Conceder ou remover permissões conforme necessário\n5. Testar acesso após alterações\n\n---\n\n### 5.
